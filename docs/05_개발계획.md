# 이천베베로드 MVP 개발 계획서

> **문서 유형**: 개발 계획서 (Development Plan)  
> **기준 문서**: `docs/PRD_bebeload.md`, `docs/FRD_bebeload.md`, `docs/TRD_bebeload.md`, `design/`, `resources/pic/`  
> **작성자 역할**: 개발 리드 (Development Lead)  
> **관리 원칙**:  
> 1. 각 EPIC이 완료될 때마다 브라우저에서 독립적으로 동작을 확인할 수 있어야 한다.  
> 2. 하나의 STORY에는 단 하나의 사용자/시스템 동작만 포함한다.  
> 3. 테스트, 보안 점검, 배포는 본 3개 EPIC 완료 후 별도 단계로 수행한다.  
> 4. `docs/FRD_bebeload.md`에 정의된 기능만 구현 대상으로 포함한다.

## 2. EPIC별 브라우저 확인 완료 기준

* **EPIC 1 완료 기준**: 사용자가 브라우저에서 홈 화면에 접속하여 검증 추천지 사진을 확인하고, 폼에서 아이 조건(17개월/2세, 유모차 사용 등)과 여행 시간을 입력하면 체류 가능 시간이 실시간 계산되고 유효성 검증을 거쳐 추천 요청이 정상 작동한다.
* **EPIC 2 완료 기준**: 사용자가 입력한 조건에 따라 규칙 기반 추천 엔진이 동작하여 브라우저에 4개 블록의 타임라인, 현장 사진, 낮잠 이동 칩, 3대 일정 메트릭, 추천 사유 및 제외 장소 브리핑이 정상적으로 출력된다.
* **EPIC 3 완료 기준**: 사용자가 타임라인의 장소를 클릭하여 8대 필수 시설 Tri-State 상태를 상세하게 확인하고, 장소 삭제·교체·한 곳 줄이기(-45분)·순서 변경을 수행했을 때 브라우저 상의 전체 일정과 여유시간이 실시간으로 재계산되어 반영된다.
